## 🚀 Как начать

### 1. Форкните репозиторий

Нажмите кнопку **Fork** на GitHub.

### 2. Клонируйте форк

```bash
git clone https://github.com/YOUR_USERNAME/nexus-browser.git
cd nexus-browser
```

### 3. Установите зависимости

```bash
npm install
```

### 4. Запустите в режиме разработки

```bash
npm run dev
```

## 📝 Правила кода

### Стиль кода

Проект использует **ESLint** и **Prettier** для автоматического форматирования:

```bash
# Проверка кода
npm run lint

# Автоматическое исправление
npm run lint:fix

# Форматирование
npm run format
```

### Основные правила

- Используйте `const` и `let`, избегайте `var`
- Всегда используйте точки с запятой
- Двойные кавычки для строк
- Отступы: 2 пробела
- Максимальная длина строки: 120 символов

### Структура проекта

```
src/
├── main.js           # Главный процесс Electron
├── preload.js        # Preload скрипт
├── site-preload.js   # Preload для сайтов
├── ui/               # UI браузера
│   ├── app.js
│   ├── index.html
│   └── styles.css
├── internal/         # Внутренние страницы
│   ├── settings.*
│   ├── profiles.*
│   └── ...
├── newtab/           # Новая вкладка
│   ├── newtab.*
│   └── nexus-search.*
└── search-engine/    # Поисковый движок
    └── engine.js
```

## 🧪 Тестирование

Перед отправкой кода убедитесь, что все тесты проходят:

```bash
# Запустить тесты
npm test

# Запустить с покрытием
npm run test:coverage

# Запустить в режиме watching
npm run test:watch
```

### Проверка сборки

```bash
# Полная проверка перед коммитом
npm run build
```

Эта команда выполнит:
- Проверку синтаксиса (`npm run check`)
- Линтинг (`npm run lint`)
- Тесты (`npm run test`)

## 📤 Pull Request

### Перед созданием PR

1. Создайте новую ветку:
   ```bash
   git checkout -b feature/your-feature-name
   ```

2. Внесите изменения и закоммитьте:
   ```bash
   git add .
   git commit -m "feat: описание изменений"
   ```

3. Обновите ветку:
   ```bash
   git pull origin main
   ```

4. Отправьте изменения:
   ```bash
   git push origin feature/your-feature-name
   ```

### Создание PR

1. Перейдите на страницу вашего форка
2. Нажмите **Compare & pull request**
3. Опишите изменения
4. Дождитесь ревью

### Формат коммитов

Используйте [Conventional Commits](https://www.conventionalcommits.org/):

- `feat:` — новая функция
- `fix:` — исправление ошибки
- `docs:` — изменение документации
- `style:` — форматирование
- `refactor:` — рефакторинг
- `test:` — добавление тестов
- `chore:` — изменения в сборке

Пример:
```
feat: добавить экспорт паролей в CSV
fix: исправить утечку памяти при закрытии вкладок
docs: обновить README.md
```

## 🐛 Сообщение об ошибках

### При создании issue укажите:

1. **Версию браузера** (например, v6.0.0)
2. **ОС** (Linux/Windows, версия)
3. **Шаги воспроизведения**
4. **Ожидаемое поведение**
5. **Фактическое поведение**
6. **Скриншоты** (если применимо)
7. **Логи** (если есть)

### Пример шаблона

```markdown
### Версия
v6.0.0

### ОС
Arch Linux 2026.01

### Шаги воспроизведения
1. Открыть браузер
2. Перейти на example.com
3. Нажать кнопку X

### Ожидаемое поведение
Страница загружается

### Фактическое поведение
Браузер зависает

### Логи
[Вставьте логи здесь]
```
